## 作業の順番（この順で行ってください）

CSV の販売期間は「11/25 0時から」にしてあるため、**CSV をアップロードした瞬間に、全商品が1円で買える状態になります。** セール用の配送グループを先に作り、その番号を入れたCSVを使ってください。番号の入っていないCSVをアップロードすると、今の送料（ネコポス500円など）のまま1円で売れてしまいます。

1. **セール用の配送グループを作り、その番号を教えてください**（[1. 送料](#1-送料1点ごとに1000円)）→ 番号入りのCSVをお渡しします
2. **商品CSVをアップロードする**（[2. 商品CSV](#2-商品csv価格と販売期間)）
3. **カートで送料を確かめる**（1点で1,000円、2点で2,000円になるか。違ったらすぐに全商品を非公開にして、ご連絡ください）
4. **トップページのコードを差し替える**（[4. ストアのトップページ](#4-ストアのトップページ)）
5. **LINE・スレッズに投稿する**（[posts.md](posts.md)）
6. **11/30 17:00 に全商品が買えなくなっているか確かめる**（[3. 終了](#3-終了11月30日月1700)）

## 1. 送料（1点ごとに1,000円）

わかっていること ✅
- 送料は、商品ごとの**配送グループ**（CSV の `postage-set` 列）で決まっています。今は 14（40商品）、3（12商品）、4（1商品）、9（1商品）の4つです。
- 今の送料の説明文（2026-11-25 にいただいた全文）に「**こちらの送料は１つの商品当たりの送料**」「同梱の発送となっても請求額は２つ分」とあります。**このストアは今も、送料を1点ごとにかけています。** なので、送料の金額を1,000円にすれば「1点ごとに1,000円」になる見込みです（実際にそうなるかは、下のカートでの確認で確かめます）。
- 今の配送方法は「60〜160サイズ宅急便（地域別）」「ネコポス（全国一律500円）」「宅急便コンパクト（地域別）」です。全国一律の送料も設定できます（ネコポスが全国一律）。
- カート設定：カートに入れる商品数の上限は **10**、すべての商品で同梱注文可。
- CSV に重量の列は無いので、以前書いた「重量で数える」方法は使いません。

### おすすめのやり方：セール用の配送グループを1つ作り、全商品をそこに移す

1. 配送グループを**新しく1つ作る**（名前の例：`閉店セール 1点1,000円`）⚠ 要確認：場所は「ストア構築」→「カート設定」→「配送方法、送料設定」の配送グループの画面。
2. その中に配送方法を**1つだけ**入れる（例：宅急便）。送料は**全国一律 1,000円**。送料のかけ方は、今の配送方法と同じ（1つの商品あたり）にする。
3. 作った配送グループの**番号**をこのチャットで教えてください。**全商品の `postage-set` をその番号にしたCSVを、すぐ作ってお渡しします**（変換スクリプトは用意済み）。
4. そのCSVをアップロードしたら、**カートで確認**（下の「設定後の確認」）。

このやり方を選んだ理由
- 今の配送グループ（14・3・4・9）と、その中の配送方法の送料を、1つずつ書き換えなくて済みます。今の設定はそのまま残ります。
- 配送方法が1つだけなので、お客様がネコポス（500円）などを選んで送料が1,000円にならない、ということが起きません。

別のやり方（参考）：今の配送グループ 14・3・4・9 の中の**すべての配送方法**の送料を全国一律1,000円に書き換える。CSVは今のままで済みますが、書き換える箇所が多く、セール後に元へ戻す手間もかかります。

参考（今の送料と比べて・計算スクリプトで確認）：60サイズの今の送料は、関東・信越・北陸・中部・関西が940円で、1,000円より安い地域です。北海道・沖縄（1,610円）、北東北・九州（1,190円）、南東北・中国・四国（1,060円）は今の送料のほうが高い地域で、1点だけのご注文では、今より安い送料になります。

- 送料無料の条件（〇円以上で送料無料など）があれば、セール中は外してください ✅。

## 2. 商品CSV（価格と販売期間）

アップロードするファイル：`csv/data/closing-sale_upload_1yen.csv`（このチャットでもお渡しします。商品データなのでリポジトリには入れていません）

| 列 | 入れた値 | 意味 |
|---|---|---|
| `price` | 1 | 販売価格 1円 ✅ |
| `sale-price` | 空欄 | セール価格を消す（残すと1円より高いセール価格が残り、矛盾するため） |
| `member-price` | 空欄 | 会員価格を消す（同上） |
| `sale-period-start` | 2026112500 | 販売期間の開始：11月25日 0時 |
| `sale-period-end` | 2026113016 | 販売期間の終了：11月30日 16時台まで（＝17:00で終了） |
| `postage-set` | （番号をいただいたら）セール用の配送グループの番号 | 全商品をセール用の配送グループに移す |
| `code` `sub-code` `original-price` | そのまま | 1文字も変えていません ✅ |

- ファイルの形式は、いただいたCSVと同じです ✅（Shift_JIS、改行は CRLF、列の並びも同じ）。
- アップロードの場所 ⚠ 要確認：ストアクリエイターPro の商品管理から、CSVのアップロード（ダウンロードしたときと同じ「項目指定」の形式）。
- **元値（`original-price`）について：** 今は元の値のままです。商品ページに「メーカー希望小売価格」などとして1円と並んで出る場合、「元値→1円」の二重価格表示になります。消したい場合は `--clear-original-price` を付けて作り直せます。
- **アップロード後に1商品だけ開いて確認してください。** 販売価格が1円になっているか。セール価格・会員価格が空になっているか。販売期間が 11/25〜11/30 になっているか ⚠ 要確認（空欄が「消す」になるか「変えない」になるかは、公式の仕様で確認できていません）。
- いただいたCSVは54商品でした。56商品のうち2商品がCSVに入っていなかった場合、その2商品は変わりません。

CSV を作り直すとき（期間を変えたい場合など）：

```
python3 closing-sale/csv/convert.py 元のCSV.csv 出力.csv --start 2026112500 --end 2026113016
（配送グループを変えるときは --postage-set 番号、元値も空欄にするときは --clear-original-price を付ける）
```

書き出す前と後に、変えた列が狙いどおりか、ほかの列が元のままかを自動で確かめます。テストは `python3 -m unittest closing-sale/csv/test_convert.py`。

## 3. 終了（11月30日（月）17:00）

- 販売期間の終わりの「時」は、その時の59分まで売れる（「17」なら17:59まで）とのことです ✅（2026-11-25 依頼者確認）。そのため、**CSV の終了は `2026113016`（16:59まで）にして、17:00 で買えなくなるようにしています。**
- 念のため、**11月30日 17:00 すぎに全商品が買えなくなっているかを見てください。** 買えるままなら、手作業で非公開にしてください。
- 17:00 を過ぎたら、トップページのコードを元に戻してください（元のコードは `toppage/original.html` に保存してあります）。

### バナーを作り直すとき

```
cd closing-sale/banner
npm install
node render.mjs
```

- `node render.mjs` は、PNG を書き出す前に中身を検査します。検査の内容：決まった文言がすべて入っていること、「15:00」・旧送料「1,500」・旧開始日「11.24 TUE」が残っていないこと、文字がはみ出したり重なったりしていないこと、送料の文字が小さすぎないこと、決めたフォントで描かれていること。1つでも外れたら `out/` には書き出さず、何が問題かを表示します。
- Playwright（Chromium 付き）が入っている環境で動きます。
