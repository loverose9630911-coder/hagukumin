# ぞうさんとなかまたち（PHP + Python 版）

生成AIで制作したオリジナル動物キャラクター **6匹（ぞう・うさぎ・カピバラ・キリン・パンダ・ビーバー）**
でつなげて消す、ツムツム系のパズルゲームです。
アプリアイコンは **ぞうさん** を PHP-GD で描き起こしています。

- **ゲームのルールは Python**（物理・チェーン判定・スコア・スキル）
- **Web アプリは PHP**（画面・セーブ・ショップ・ランキング・画像生成）
- ブラウザ側の JavaScript は **描画と指の動きを送るだけ**

iPad へは、このサーバー版をそのまま入れて遊べます → [iPad に入れる](#ipad-に入れる)。

画像素材・音声素材・外部ライブラリは一切使っていません。キャラクターの絵は
PHP-GD が図形を組み合わせてその場で描き出し、効果音と BGM は WebAudio で合成しています。

---

## うごかしかた

```bash
cd tsumtsum
bin/serve                 # → http://localhost:8080
```

`bin/serve` が Python のエンジン（ポート 8765）と PHP の Web アプリ（ポート 8080）を
両方立ち上げます。必要なら初回に config とキャラ画像も自動で作ります。

```bash
make setup   # キャラ定義の書き出し＋画像の生成だけ
make static  # iPad 用の静的サイト（dist/）を書き出す
make test    # エンジンのテスト（42 件）
make sim     # ブラウザ無しで自動プレイしてバランスを確認
make assets  # キャラ画像とアプリアイコンを描きなおす
```

必要なもの: PHP 8.1 以上（`gd` / `pdo_sqlite` / `curl`）、Python 3.9 以上（標準ライブラリのみ）。

## なぜこの分担なのか

ブラウザで動くゲームである以上、60fps の描画と指の追従だけは JavaScript が担当するしかありません。
そこで「**ルールと判定は 1 か所（Python）だけに置く**」という形にしました。

```
  ブラウザ                    PHP                        Python エンジン
 ┌──────────┐        ┌──────────────┐        ┌────────────────────┐
 │ なぞった   │  ids   │ セッション管理  │  ids   │ チェーン判定        │
 │ ツムの ID  │ ─────> │ プレイヤー保存  │ ─────> │ 消去・スコア・物理   │
 │           │        │ ランキング     │        │ 盤面を静止させる     │
 │ 静止盤面を │ <───── │              │ <───── │ 静止盤面 + スコア    │
 │ 補間して描く│  盤面   │              │  盤面   │                    │
 └──────────┘        └──────────────┘        └────────────────────┘
```

- ブラウザが送れるのは「どのツムをなぞったか」だけ。**スコアは送れません。**
- 消去・得点・時間はすべてサーバー側で決まるので、ブラウザを書きかえても点数を偽装できません。
- 盤面は 1 手ごとに **完全に静止した状態** で返ってきます。ブラウザはその間を補間して
  「落ちてくる」ように見せるだけなので、物理エンジンをクライアントに持つ必要がありません
  （ルールの二重実装がない）。

1 手あたりのエンジンの計算は実測 **平均 39ms / 最大 75ms**。
落下アニメーション（0.42 秒）のあいだに終わるので、待たされる感じはありません。

## iPad に入れる

サーバー版（PHP + Python）をどこかで動かして、その URL を iPad の Safari で開き、
**「ホーム画面に追加」**すれば、ふつうのアプリと同じように遊べます。

### どこで動かすか

| | A. 家のパソコン | B. クラウド（Docker） |
| --- | --- | --- |
| 用意するもの | PHP と Python が入ったパソコン | Render などのアカウント |
| 費用 | 無料 | 無料プランあり（下記の注意） |
| 遊べるとき | パソコンをつけていて、同じ Wi-Fi のとき | いつでも・どこでも |
| 手間 | `bin/serve` を実行するだけ | 最初に 1 回だけ設定 |

まずは **A** で試して、気に入ったら **B** に移すのがおすすめです。

### A. 家のパソコンで動かす

```bash
cd tsumtsum
bin/serve
```

こう表示されます。

```
▶ PHP を起動します
   このパソコン  →  http://localhost:8080
   iPad など     →  http://192.168.1.23:8080   （同じ Wi-Fi につないでください）
```

下の `http://192.168.1.23:8080` を iPad の Safari で開きます（数字はおうちごとに違います）。
パソコンを閉じると遊べなくなるので、遊ぶときだけ立ち上げてください。

> つながらないときは、パソコンのファイアウォールが 8080 番をふさいでいないか確認してください。
> Mac なら「システム設定 → ネットワーク → ファイアウォール」です。

### B. クラウドに置く（いつでも遊べる）

`Dockerfile` を用意してあるので、Docker が動く場所ならどこでも置けます。

**Render を使う場合**（リポジトリ直下の `render.yaml` を読んでくれます）

1. <https://dashboard.render.com/> → `New` → `Blueprint`
2. このリポジトリを選んで `Apply`
3. 発行された `https://〇〇.onrender.com` を iPad の Safari で開く

> 無料プランは 15 分アクセスがないと眠るので、久しぶりにひらくと 30〜60 秒待たされます。
> 娘さんを待たせたくない場合は `render.yaml` の `plan: free` を `starter` に変えてください（有料）。

**手元やレンタルサーバーの Docker で動かす場合**

```bash
cd tsumtsum
docker compose up -d          # → http://localhost:8080
```

セーブデータ（コイン・所持キャラ・ランキング）は `data/` に残ります。

### iPad のホーム画面に追加する

1. **Safari** でその URL を開く（Chrome だとホーム画面に追加できません）
2. **共有ボタン** <kbd>↑</kbd> をタップ
3. **「ホーム画面に追加」** → そのまま「追加」

ぞうさんのアイコンがホーム画面に並びます。
アイコンから起動すると Safari のバーが出ない全画面になります。

### サーバー版のいいところ

- **スコアがごまかせない** — 消去も得点も時間もサーバーが決めるので、ブラウザをいじっても効きません
- **ランキングがみんなで共有される** — iPad からもパソコンからも同じ記録が見えます
- **セーブが 1 か所** — 端末を変えても、同じサーバーにつなげば続きから遊べます

### オフラインで遊べる静的版もあります

サーバーを用意せず、Netlify などに置いてオフラインで遊びたいときは `make static` で
`dist/` を書き出せます（[Netlify Drop](https://app.netlify.com/drop) にドラッグ＆ドロップ）。
ゲームの中身は同じですが、セーブはその iPad の中だけ・スコアは手元で計算になります。

## 中身のはなし

### 物理（`engine/zousan/physics.py`）

速度をそのまま積分すると、支えられた円に重力が溜まりつづけて山が永久に振動します。
そこで **位置ベース（PBD）** にしています。

1. 重力を加えて仮の位置へ動かす
2. めり込みを「位置」で 5 回くり返し解く
3. 実際に動いた距離から速度を作り直す

支えられた円は位置が動かない＝速度が自動的に 0 になるので、山がぴたりと止まります。
さらに次の 3 つを入れて、1 手あたり 39ms に収めました。

- **ねむり**: 動きが止まった円を計算から外す（盤面のほとんどは動かない）
- **ペアの使い回し**: ぶつかりそうな組み合わせを 1 ステップに 1 回だけ作る
- **摩擦**: 接触面の横ずれを打ち消す。これが無いと円が転がりつづけて何秒も静止しない

打ち切りの判定は「下向きの速さ」だけを見ています。ゆるい山は横方向にいつまでも
小さくゆれるので、速さ全体で判定すると毎回上限まで回ってしまい、
まだ落ちている途中のツムをそのまま固めてしまう（宙に浮いたまま止まる）ためです。
さらに仕上げとして、どこにも触れていない円が残っていたら着地するまで回すので、
浮いたツムは絶対に残りません（`World.floating_bodies()` とテストで担保）。

### 音（`public/assets/js/audio.js`）

音源ファイルを持たず、WebAudio でその場で合成しています。
つなぐたびに音階が上がり、フィーバー中は BGM が速くなります。
プレイ画面右上の ♪ ボタンでオン／オフでき、設定は localStorage に残ります。

### キャラクターの絵（`tools/render_assets.php`）

画像ファイルを持たず、GD の図形だけで描いています。
4 倍の大きさで描いてから縮めることで、輪郭のギザギザを消しています。
色や種族は `characters.py` の定義を読むので、**キャラを増やすときは Python 側を直すだけ**です。

```python
# engine/zousan/characters.py に 1 件足す
Character(
    id="kuma", name="くまさん", tagline="もりの ともだち",
    kind="beaver",              # 描きかたの種類（render_assets.php の switch）
    body="#C08A5A", shade="#7A5230", inner="#EBD3B6",
    cheek="#FF9C9C", accent="#E8C98A", price=2000,
    skill=Skill(id="burst", name="はちみつバースト", desc="まるく 消す",
                need=[24, 22, 20, 18, 16], power=[110, 126, 142, 160, 180]),
)
```

```bash
make assets   # 定義の書き出し → 画像の生成。選択画面にもゲームにも自動で出てくる
```

新しい絵の描きかたを増やしたいときは `tools/render_assets.php` の `drawByKind()` に
`case` をひとつ足します。新しいスキル効果は `engine/zousan/skills.py` の `TABLE` に足します。

### 静的版のエンジン（`public/assets/js/engine-local.js`）

オフラインで遊ぶには、ルールがブラウザの中に無いといけません。
そこで Python エンジンと**同じ手順**で動く JavaScript 版を置いています。
数値はどちらも `config.json`（もとは `engine/zousan/` の Python）を読むので、
二か所で数字を持つことはありません。

描画側（`client.js`）は、サーバーに投げるかわりにこのエンジンへ問い合わせるだけなので、
**サーバー版と静的版で同じコード**が動いています。

```js
// client.js の中身（抜粋）
if (window.LocalEngine && window.LocalEngine.enabled) {
  return LocalEngine.request(url, body);   // 静的版：ブラウザの中で計算
}
return fetch(url, ...);                    // サーバー版：PHP → Python
```

### データ

`data/zousan.sqlite` が自動で作られます（プレイヤー・所持キャラ・経験値・ランキング）。
プレイヤーの見分けは Cookie のセッションだけで、ログインは要りません。

## 本番に置くとき

- Web ルートを `public/` に向けてください（`src/` と `engine/` は公開されません）。
- Python エンジンは `127.0.0.1` で待ち受けます。外に出さないでください。
  接続先は環境変数 `ENGINE_URL` で変えられます。
- エンジンは systemd などで常駐させ、PHP は Apache / nginx + PHP-FPM から動かすのが手軽です。
