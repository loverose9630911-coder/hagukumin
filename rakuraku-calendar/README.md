# らくらく連絡帳 → Googleカレンダー 自動登録

「〇〇カレンダー.pdf」を Google Drive の決まったフォルダに入れると、次のことが自動で行われます。

1. 15分以内に PDF を読み取る（マス目のカレンダーは、マスごとに日付と予定を読み分ける）
2. 予定のある日ごとに、love.rose のカレンダーへ終日の予定として登録する
3. 各予定に「前日 17:00」の通知を付ける（ほかの既定の通知は外す）
4. 登録した内容を love.rose あてにメールで知らせる

動かす場所は、love.rose（love.rose.9630911@gmail.com）の Google アカウントの中にある Google Apps Script です。費用はかかりません。

このアカウントのカレンダーと Drive は Claude との会話からも見られます。そのため、実物の PDF に合わせた読み取りの調整や、登録結果の確認を Claude に頼めます。

## 初回の設定（1回だけ・パソコンのブラウザ推奨）

1. **love.rose.9630911@gmail.com** の Google アカウントでログインし、<https://script.google.com/> を開いて「新しいプロジェクト」を押す
2. 左の歯車「プロジェクトの設定」を開き、「『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェックを入れる
3. 左の「エディタ」に戻って `appsscript.json` を開き、中身をすべて消して、このフォルダの `appsscript.json` を貼り付ける
   - これで Drive API の有効化と、日本時間の設定が同時に済みます
4. 最初からある `.gs` ファイル（日本語画面では `コード.gs`）を開き、中身をすべて消して、このフォルダの `Code.gs` を貼り付けて保存する
5. 画面上部の関数の選択欄で `setup` を選んで「実行」を押す
   - 承認の画面が出たら love.rose.9630911@gmail.com を選んで「許可」を押します
   - 「Google で確認されていません」と出た場合は、「詳細」→「（プロジェクト名）に移動」→「許可」の順に進みます
6. 下の実行ログに `【設定完了】` と出れば終わりです
   - `【要確認】` が出た場合は、その行に書かれた内容を直してから `setup` をもう一度実行します

このあと Drive に「らくらく連絡帳カレンダー」というフォルダができています。

## 毎月の操作（iPhone）

1. らくらく連絡帳で「〇〇カレンダー.pdf」を開く
2. 共有のメニュー（「ファイルに保存」が出るのと同じメニュー）から「Drive」を選び、フォルダ「らくらく連絡帳カレンダー」に保存する
3. 15分ほど待つと、カレンダーに予定が入り、結果のメールが届く

iPhone の「ファイル」アプリに保存しただけでは登録されません。Drive のフォルダに入れてください。

- iPhone に Google Drive アプリを入れ、love.rose でログインしておく必要があります。
- 通知を受け取るには、iPhone の Google カレンダーアプリに love.rose を追加し、通知を許可しておきます。
- らくらく連絡帳の PDF 画面に共有ボタンが出るかは未確認です。出ない場合は Claude に伝えてください。

### 最初の1回だけの確認

最初に登録された予定を Google カレンダーで1件開き、通知が「前日 17:00」と表示されているか確認してください。違う時刻なら Claude に伝えてください。
検証用の予定では「前日 17:00」と表示されることを確認済みです。

## 読み取り方

### マス目のカレンダー（らくらく連絡帳の「〇〇カレンダー.pdf」はこの形）

Excel などで作られた文字入りの PDF は、PDF の中の「どの文字が、どの位置にあるか」を直接読み、マス目ごとに分けます。

- 曜日の見出し「日〜土」の位置で、どの列かを決めます。
- 各週の日付の数字の位置で、どの週かを決めます。数字の右上の小さな祝日名も、その日に入ります。
- 予定のある日ごとに、終日の予定を1件登録します。予定名は、マスの中の行を「 / 」でつないだものです。
  - 例：「内科健診 / ピカットらんど（ダンス）」
- 「（」や「＆」で始まる行は、前の行の続きとしてつなげます。
- 予定の説明欄には、マスの中の行をそのまま1行ずつ入れます。
- 表の下の「＊」の注意書きは日付がないため、予定には入れず、結果のメールで知らせます。
- PDF の1日の曜日と月の日数を、実際の暦と照らし合わせます。合わないときは登録せず、要確認のメールを送ります。

### マス目でない PDF（スキャンした画像など）

Google ドキュメントへの変換（文字認識）で文字を取り出し、次の形の行を拾います。

| 例 | 登録される予定 |
|---|---|
| `5日(土) 運動会` | 5日・運動会 |
| `５日（土）　運動会`（全角） | 5日・運動会 |
| `5(土) 運動会` | 5日・運動会 |
| `10/5(土) 運動会` | 10月5日・運動会 |
| `10月5日(土) 運動会` | 10月5日・運動会 |
| `14日(水) 誕生会 10:00〜` | 14日・「誕生会 10:00〜」（時刻は予定名に残し、終日予定で登録） |

次の行は登録しません。

- 日付だけで予定名がない行（カレンダーのマス目など）
- 「20日までに提出してください」のような、日付のすぐ後が「まで・頃・以降・以内」の行
- 存在しない日付（11月31日など）

何年何月かは、ファイル名の「10月」から決めます。年は次の順で決めます。

1. 本文に「2026年10月」「令和8年10月」があれば、その年
2. 本文に「令和8年度」「2026年度」があれば、年度から決める。4〜12月はその年、1〜3月は翌年
3. どちらもなければ、PDF を入れた日にいちばん近い年。12月に入れた「1月カレンダー.pdf」は翌年の1月になる

## 困ったとき

- **間違った予定が登録された**：スクリプトの画面で `undoLastImport` を選んで実行すると、直前に自動登録した分だけが消えます。
- **予定が読み取れなかった**：結果メールの「読み取った文字」か PDF そのものを Claude に送ってください。読み取り方を実物に合わせます。
- **同じ PDF を入れ直した**：すでにある予定は重ねて登録しません。

## 【任意】らくらく連絡帳から Gmail に PDF 付きメールが届く場合

メールで届くなら、Drive に入れる操作も不要にできます。

1. スクリプトに `GmailImport.gs` を追加して貼り付ける
2. `Code.gs` の `GMAIL_SENDER` に、らくらく連絡帳からのメールの送信元アドレスを入れる
3. `setup` をもう一度実行し、Gmail の許可を出す

メールが届くかどうかは未確認です。Gmail の読み取り許可を増やさないよう、初期状態では入れていません。

## 設定を変えたいとき

`Code.gs` の先頭の `CONFIG` で変えられます。

| 項目 | 初期値 | 意味 |
|---|---|---|
| `NOTIFY_HOUR` | `17` | 前日の何時に通知するか |
| `CHECK_EVERY_MINUTES` | `15` | 何分ごとにフォルダを確認するか（1/5/10/15/30） |
| `CALENDAR_ID` | 空 | 空ならメインカレンダー。別のカレンダーに入れたいときに ID を入れる |
| `FOLDER_NAME` | `らくらく連絡帳カレンダー` | PDF を入れる Drive フォルダ名 |

変えたあとは `setup` をもう一度実行してください。

## Claude のルーティーン用の読み取りプログラム

`tools/pdf-to-events.js` は、カレンダーの PDF を読んで、登録する予定の一覧を JSON で出します。読み取りは `Code.gs` と同じ処理で、Google には接続しません。

```
node rakuraku-calendar/tools/pdf-to-events.js --pdf 10月カレンダー.pdf --name 10月カレンダー.pdf --ref 2026-09-30 --from 2026-10-18
```

- `--from` を付けると、その日より前の予定は出しません。
- base64 の文字で受け取った場合は、`--pdf` の代わりに `--base64 ファイル` を使います。
- 読めないときは `{"ok":false,"error":"理由"}` を出し、終了コード1で終わります。

## テスト

```
node rakuraku-calendar/tests/run-tests.js
```

Google のサービスを模した環境で `setup` と `checkNew` を実際に動かし、ルーティーン用の読み取りプログラムも含めて30項目を確認します。本物の Google アカウントにはアクセスしません。

- マス目の読み取りは、テストの中で組み立てる架空の「11月のカレンダー PDF」で確かめます。文字の符号化や圧縮は実物と同じ作りにしてあり、家庭の情報は入っていません。読み取りの試験用に簡略化しているため、一般の PDF 閲覧ソフトでは開けません。
- 実物の PDF はリポジトリに入れていません。手元で実物を通すときは、次のように実行します。正解ファイルは `[[日, "予定名"], ...]` の形の JSON です。

```
RAKURAKU_REAL_PDF=実物.pdf RAKURAKU_REAL_NAME=10月カレンダー.pdf RAKURAKU_REAL_EXPECTED=正解.json node rakuraku-calendar/tests/run-tests.js
```
